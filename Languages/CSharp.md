# Стиль написания кода на C#

Следуй официальным конвенциям Microsoft C# Coding Conventions:
https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/coding-conventions

Именование
- PascalCase: типы, публичные члены, константы.
- camelCase: параметры и локальные переменные.
- `_camelCase`: приватные поля.
- Интерфейсы начинаются с `I`, асинхронные методы заканчиваются на `Async`.
- Без сокращений и венгерской нотации: имя отражает назначение.

Структура кода
- Один файл — один тип (класс, структура, запись, интерфейс, перечисление). Имя файла совпадает с именем типа. Исключение: вложенные типы.
- Всегда указывай модификатор доступа явно (`private` у членов, `internal` у типов) и выбирай минимально возможную видимость.
- Методы короткие и выполняют одну задачу.
- Для `IDisposable` используй `using`-декларации.
- Для определения пустой строки всегда используй string.Empty вместо "".

Форматирование
- Фигурные скобки в стиле Allman.
- Отступ: 4 пробела, символы табуляции не используй.
- `var` только когда тип очевиден из правой части.
- file-scoped namespace. Но сначала проверь версию языка. Если версия языка в проекте поддерживает file-scoped namespace, то можно его применить.

Комментарии
- Читаемость обеспечивают понятные имена, а не комментарии.
- Комментарий должен объяснять «почему», а не «что», и  быть максимально лаконичным (занимать одну-две строки).
- Язык комментариев и XML-документации: русский.

Асинхронность
- `CancellationToken` ставь последним параметром асинхронных методов и пробрасывай дальше.
- Не используй `async void` (кроме обработчиков событий), `.Result` и `.Wait()`.
- `ConfigureAwait(false)` применяй в библиотечном коде, но не в ASP.NET Core и UI.

Обработка ошибок
- Предпочитай guard clauses с ранним выходом глубокой вложенности.
- Выбрасывай конкретные типы исключений. Не лови `Exception` без необходимости, не глотай исключения молча, используй `throw;`, а не `throw ex;`.
- Для ожидаемых сбоев используй `TryXxx`-методы или результат операции, а не исключения.

Зависимости
- Внедряй зависимости через конструктор. Если это возможно, то не используй Service Locator и изменяемое статическое состояние. А если все-таки приходится их использовать, то всегда сообщай о таком поведении и спроси разрешения перед внедрением.
- Не добавляй сторонние NuGet-пакеты без явного запроса.
