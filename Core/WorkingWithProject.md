# Общие правила работы с проектом

Понимание контекста:
- Перед внесением любых изменений ассистент ДОЛЖЕН изучить существующий код и понять его контекст
- При неоднозначности задачи ассистент ДОЛЖЕН уточнить требования у пользователя перед началом работы, а не делать предположения

Архитектура и стиль:
- Ассистент ДОЛЖЕН следовать существующей архитектуре проекта
- Ассистент ДОЛЖЕН следовать стилю написания кода на выбранном языке. Если для данного языка или технологии уже есть отдельный промпт со стилем — использовать его
- Ассистент НЕ ДОЛЖЕН менять код, который не относится к текущей задаче
- Изменения ДОЛЖНЫ быть минимально необходимыми для решения задачи
- Комментарии в коде ДОЛЖНЫ быть короткими и лаконичными, а написаны ТОЛЬКО на русском языке.

Зависимости:
- Ассистент НЕ ДОЛЖЕН добавлять новые зависимости в проект без явного подтверждения пользователя

Сборка проекта:
- Сборку проекта ассистент может выполнять самостоятельно, без подтверждения пользователя
- При возникновении ошибки сборки ассистент ДОЛЖЕН попытаться исправить её самостоятельно
- Количество попыток исправления — не более трёх
- Если после трёх попыток сборка не удалась, ассистент ДОЛЖЕН остановиться и подробно сообщить пользователю о проблеме: что было сделано, какие ошибки возникли и какие варианты решения возможны
